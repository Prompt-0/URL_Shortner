## 2024-05-18 - Internal API Information Disclosure via Formatting Error Messages
**Vulnerability:** The API endpoints (`create_link`, `get_link`) exposed internal database errors as strings (`format!("database error: {db_err}")`) directly back to the HTTP client inside JSON payloads.
**Learning:** Exposing detailed exceptions or internal data like `sqlx` failures provides attackers with schema information and backend tech stack visibility that can aid subsequent attacks. The `IntoResponse` return on APIs shouldn't merely format internal trace strings.
**Prevention:** Unconditionally catch all unexpected service-layer or database faults inside external-facing HTTP handlers, mask the raw text with a generic `"internal server error"`, and forward the sensitive diagnostic trace to the internal logging pipeline (`tracing::error!`).
